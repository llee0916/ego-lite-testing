# 执行、数据与报告

## 环境与数据

- 生产环境或无法确认环境性质时按只读处理：不创建、保存、编辑、删除、导入、上传、修改配置或状态、注册、发送通知或审批。允许导航、查询、筛选、排序、分页及查看表单；下载/导出仅在用户明确允许时执行。用户明确授权生产中的具体写操作时，记录授权及范围，仅执行该范围。
- 测试环境中使用唯一标记和专属记录，不修改原有记录；先考虑清理方式和关联副作用。发生真实通知或不可逆原有数据操作且授权不明时先确认。工具或清理能力不足不减少其他场景覆盖。
- 台账记录测试记录 ID、名称、用途、关键字段、初始及最终状态、清理责任和结果。优先清理本轮创建的数据并重新查询确认；没有删除入口时不猜接口，不把停用当作删除，报告残留和人工待办。
- 不将凭证写入长期脚本、报告、快照说明或日志。确需临时脚本时隔离凭证并在使用后删除；证据避免包含令牌及无关个人信息。

## ego-browser 操作

- 创建独立运行目录保存脚本、结果和证据。PowerShell 下按照当前 ego-browser 指南使用 UTF-8 `.mjs` 分轮执行；脚本使用绝对路径，每轮新建文件，不重放含写操作的旧轮次。
- 基于当前页面快照选择唯一目标；操作后等待实际导航、加载或业务状态。`page.evaluate()` 仅用于只读提取与诊断，不直接修改 DOM、调用应用内部方法或写接口替代 UI。
- 保存或提交超时后，先检查页面、弹窗和目标记录；结果不明时不盲目重复写操作。下载应先注册事件，并在同一轮保存文件；涉及生产数据时先遵守上述授权限制。
- 登录页、等待或截图失败时分层诊断，保持同一个 TaskSpace；截图故障不等于产品故障。若项目提供经授权的 ego lite 启动脚本，可按本机规则运行并检查健康状态与日志，不终止用户浏览器、不清理共享状态来绕过问题。

## 结果与证据

- 每项使用独立状态：通过（预期和结果均有证据）、失败（有规则依据且实际不符）、阻塞（已尝试但前置条件或工具等阻碍）、未执行、不适用（页面无功能或用户排除）、待业务确认（已观察行为但预期规则不明）。不重复计数，不将工具或定位错误判为产品缺陷。
- 缺陷记录条件、步骤、输入、预期依据、实际结果、影响、URL、时间、实际视口和证据。尽量截图；失败时保留快照、URL 和采集错误。截图必须实际查看后才能用于视觉判断；没有视觉证据时明确限制。
- 报告写明环境、范围、实际设备和视口、工具版本、账号角色（无密码）、需求来源及假设；按发现的功能点说明已测、结果和证据，尤其分别列明排序列、筛选条件及选项、批量操作、导入及各导出模式的覆盖边界。
- 对阻塞或未执行入口说明已检查到哪一步、具体原因和剩余风险；对不适用说明原因。列出未覆盖的角色、设备、并发等；不以观察入口、HTML 属性或 HTTP 成功代替 UI 功能通过。
- 输出数据台账、清理情况和人工待办，最终提供工作区内报告链接。结果台账是内部执行和收口依据，不要求事前向用户展示场景清单。
